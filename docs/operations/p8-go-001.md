# P8-GO-001 production-like readiness rehearsal

This is an automated, read-only readiness contract. It does not change the
production database, provider configuration, LINE webhook, or citizen traffic.
The unit gate validates the inputs and the rollback sequence; an external
deployment job may execute the same sequence when its target and credentials
are available.

## Rehearsal sequence

1. Verify the immutable release manifest, candidate, SBOM and source hashes.
2. Verify the timestamp-ordered Supabase migration chain and run it against an
   isolated PostgreSQL target with synthetic tenant fixtures.
3. Run health, LIFF safe landing, complaint fallback, admin boundary and
   tenant-isolation smoke checks.
4. Verify backup/PITR metadata (`RPO=15m`, `RTO=4h`) and isolated restore
   constraints. Never overwrite production during restore rehearsal.
5. Verify application/configuration/index/theme/Rich Menu rollback metadata.
6. Record the result and leave production traffic unchanged when a target or
   credential is unavailable. The deployment job retries the dependency.

## Rollback sequence

- Disable only the affected feature flag or provider consumer.
- Redeploy the last verified signed artifact and keep the database backward
  compatible; use a forward fix for schema changes.
- Preserve complaint, intake, audit, backup and evidence records.
- Run health and synthetic smoke checks, then restore traffic only when the
  checks reconcile.

## Machine checks

```text
python -m unittest scripts.test_recovery_contract -v
python scripts/unit_gate.py --validate-only
```

The readiness file is
`docs/qa/p8-go-001-readiness.json`. It is intentionally marked
`productionMutationAllowed: false` and contains no provider secret or PII.

## Limitations

The repository cannot prove a live Supabase PITR restore, Vercel promotion, or
LINE provider delivery without external targets. Such work remains an
execution dependency and is fail-closed; it does not become a false unit pass.
