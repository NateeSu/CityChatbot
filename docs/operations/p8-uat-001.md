# P8-UAT-001 automated municipal acceptance harness

This artifact is the executable-UAT companion for the local synthetic journey
harness. It defines the role coverage and the operator-facing checks without
claiming that an external participant, LINE account, or production record was
used. The unit gate is the source of closure; external execution remains an
advisory runtime activity.

## Run

```text
python -m unittest scripts.test_e2e_certification -v
python scripts/e2e_certification.py --base-url http://127.0.0.1:3224
```

The report must be JSON, immutable after creation, reconciled, and must contain
`productionDataTouched: false`. A missing provider or staging target is
`NOT_AVAILABLE`, never a synthetic PASS.

## Role journeys

### Citizen {#citizen}

Open the LIFF surface, submit a complaint with an idempotency key, replay the
same request, inspect the citizen tracking projection, and verify loading,
empty, error, offline, permission and expired-session states. User-facing
messages are Thai and the citizen never receives internal notes or raw provider
errors.

### Staff {#staff}

Open the tenant-scoped inbox, filter within the permitted queue, assign a
complaint, add an internal note, and publish only an allowed public update.
Verify that a different tenant and an unauthorized department cannot read or
mutate the record.

### Department head {#department-head}

Verify department scope, assignment, status transition, optimistic concurrency
conflict handling, and the canonical handoff path for work outside the
department.

### Knowledge {#knowledge}

Verify that an uploaded object is quarantined, parser/index validation runs,
activation is unit-gated, active generations remain immutable, and rollback
does not activate an unverified or stale source.

### Public relations {#public-relations}

Verify news draft validation, schedule/publish/archive transitions, revision
rollback, tenant scope, and audit event creation. No draft or evaluation-only
content is treated as an active citizen source.

### Tenant admin {#tenant-admin}

Verify role-scoped settings, light/dark/high-contrast theme behavior, session
expiry and permission denial, audit visibility, and configuration rollback.

### Executive {#executive}

Verify that KPI values and exports come from server-derived facts, filters
reconcile to the raw count, stale data is disclosed, and AI narrative text
cannot invent a number, date, SLA, price, fee, or eligibility result.

## Safe handoff {#handoff}

Insufficient, ambiguous, conflicting, stale, or person-specific evidence must
produce only `CLARIFY` or `HANDOFF` with a canonical reason code. The harness
must assert citation/evidence coverage and tenant isolation; an LLM judge alone
is not sufficient for numeric, date, unit, branch, eligibility, or fee claims.

## Rollback {#rollback}

Disable the narrowest affected feature, preserve complaint/intake/audit data,
restore the previous signed artifact/configuration/index/theme, run health and
smoke checks, and reconcile before restoring traffic. Do not overwrite
production data or delete evidence as part of UAT.

## Limitations

The local harness cannot prove external LINE delivery, municipal participant
usability, provider availability, or a live staging deployment. Those results
remain explicitly `NOT_AVAILABLE` until the corresponding external target is
configured; that limitation does not block the automated unit gate.
