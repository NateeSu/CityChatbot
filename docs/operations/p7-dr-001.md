# P7-DR-001 Backup, PITR และ isolated restore contract

สถานะการทดสอบนี้เป็น deterministic rehearsal ที่ใช้ synthetic tenant เท่านั้น
และไม่อ่านหรือเขียน production data. เป้าหมายของ contract คือทำให้ backup/restore
worker มี input/output ที่ตรวจสอบได้ก่อนใช้ Supabase PITR จริงใน environment แยก

## Versioned targets

- RPO: `15m` (`NFR-DR-001`)
- RTO: `4h` (`NFR-DR-001`)
- restore target: isolated database/storage namespace เท่านั้น
- production restore: ห้าม overwrite production; ใช้ forward fix หรือ rollback artifact

## Backup inventory

Backup manifest ต้องระบุ database snapshot/PITR position, storage object inventory,
configuration version, secret key-version reference (ไม่ใช่ค่า secret), source RC,
checksum และ generated-at. ทุก item ต้องมี tenant scope และ retention/legal-hold
policy reference. Plaintext token/password/API key ห้ามอยู่ใน manifest หรือ log.

## Isolated restore sequence

1. verify manifest signature/checksum and reject missing or corrupt items;
2. restore database into an isolated target using a synthetic tenant pair;
3. restore storage objects under tenant-bound keys;
4. reconcile counts, checksums, composite tenant links, FK links, RLS/forced-RLS,
   append-only audit, citation/document versions and object permissions;
5. measure `restoreCompletedAt - restoreStartedAt` and compare to RTO;
6. discard isolated target after evidence is written.

Missing backup, checksum mismatch, cross-tenant link or disabled RLS is an alert and
fail-closed result. No production mutation is part of this task.

## Rollback

Discard only the isolated restore target and preserve the immutable backup evidence.
If a production incident is detected, disable the affected feature and deploy the
last-known-good application/configuration; do not delete or rewrite production data.
