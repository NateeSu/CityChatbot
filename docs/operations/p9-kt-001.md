# P9-KT-001 Operations handoff

This runbook is the machine-readable handoff companion for CityChatbot. It
contains references only; credentials, provider tokens, user identifiers and
PII stay in the production secret store and are never copied into this file.

## Current production references

- Hosting: Vercel project `city-chatbot`; production deployment is sourced from
  the `main` branch.
- Database: Supabase project reference `qiaklpfojbdajpskmjze`.
- Messaging: dedicated LINE pilot channel; channel token and webhook secret are
  server-only environment references.
- Runtime migration: `supabase/migrations/20260813010000_line_chat_runtime.sql`.
- Primary rollback: disable the affected tenant/feature flag, route to
  handoff, then redeploy the last-known-good Git revision.

## Safe operational sequence

1. Run the repository unit gate for the affected task and preserve its report
   hash.
2. Apply database migrations forward-only against the intended environment;
   verify RLS, function-only grants and tenant composite constraints.
3. Configure only secret references in Vercel Production. Keep
   `LINE_CHAT_RUNTIME_ENABLED=false` until the configuration probe is green.
4. Run signed webhook, duplicate, retry, grounded-answer and handoff probes.
5. Enable the smallest tenant-scoped feature flag; monitor health, sampling,
   reconciliation, SLO and cost signals.
6. If any critical signal fails, force handoff or rollback using the idempotent
   operation and preserve the audit/evidence record.

## Recovery

- LINE/provider failure: retain the inbox, retry delivery, and route new
  traffic to handoff; never roll back a complaint business mutation.
- Knowledge or evidence failure: keep the last active approved generation and
  abstain from unsupported answers.
- Database migration issue: stop the feature, use a forward-compatible fix or
  restore the last-known-good application revision; do not rewrite audit data.
- Vercel deployment issue: restore the previous production deployment and
  re-run health/synthetic probes before re-enabling traffic.

## Ownership and cadence

The system unit-gate actor owns automated task closure and retry. Hypercare
sampling is daily and tenant-scoped. Content freshness, source expiry and
certified RAG regression are maintained by the scheduled jobs described in
`plan.md`; human feedback is advisory telemetry and cannot reopen a green unit
gate.
