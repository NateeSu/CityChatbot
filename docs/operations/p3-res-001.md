# P3-RES-001 complaint recovery runbook

Scope: complaint submission and optional integrations when OpenRouter, embedding, LINE push, map/geolocation or reverse-geocode is unavailable.

## Safety invariant

The complaint transaction commits the tenant-scoped intake queue, complaint number, `RECEIVED` state, first timeline and domain outbox before optional integration work. Integration failure never rolls back the saved complaint. The citizen can continue with a manual address, and staff can view/assign the complaint from the intake queue.

## Failure matrix

| Dependency | Immediate behavior | Recovery action |
|---|---|---|
| OpenRouter | Chat returns canonical `HANDOFF` / `SYSTEM_ERROR`; complaint remains in intake queue | Inspect queued `OPENROUTER` job; retry after provider health is restored |
| Embedding | Source/version remains unchanged; work is queued for retry | Run reconciliation worker; do not activate a partial index |
| LINE push | Complaint state remains committed; delivery/job is visible and retryable | Retry the same dedupe key; do not create a second business event |
| Map | Keep manual address/text and allow submission | Retry map enrichment; never make map availability a submission prerequisite |
| Reverse geocode | Keep the user-supplied location; omit enrichment | Retry enrichment; no status or complaint data rollback |
| Worker crash | Lease expires and job becomes `RETRY_WAIT` or `DEAD` after max attempts | Start another worker with a new owner; inspect dead jobs before replay |

## Operator procedure

1. Confirm the complaint exists in the tenant intake queue and has a valid complaint number.
2. Check the reconciliation list for the same tenant and complaint. Use the integration and dedupe key; never create a new complaint to retry an integration.
3. Check provider health and rate limits. Redacted error codes are `TIMEOUT` or `EXTERNAL_DEPENDENCY_FAILED`; do not place tokens, phone numbers or raw provider payloads in notes.
4. Run one reconciliation worker. The job lease prevents concurrent completion; heartbeat long-running work.
5. Verify the job reaches `SUCCEEDED`. If it reaches `DEAD`, record an audited operational reason before an authorized replay.
6. For persistent LINE failure, leave business state unchanged and use the notification/admin retry path.
7. For persistent map failure, keep the manual address path enabled and communicate the limitation to staff.

## Rollback / feature flags

- Disable optional AI, map and notification consumers independently; keep complaint intake and the default queue enabled.
- Do not delete or rewrite complaint, number, timeline, outbox or retry records.
- Re-enable one integration at a time after `pnpm test:all`, the relevant provider contract and a synthetic retry pass.

The certified local recovery suite covers all five integration failure classes, default queue fallback, idempotent submission, staff visibility/manual assignment, retry without duplicate jobs, lease reclaim and canonical chat handoff.
